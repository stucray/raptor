# Capture sample

Four **synthetic** capture files, generated by

    python3 tools/samples/make_synthetic_capture_sample.py \
        --out capture/src/test/resources/capture-sample

They replaced four captures copied verbatim off the stream (#303). Betfair's
captures are licensed for personal use and may not be committed; the real ones
stay in custody (`$RAPTOR_DATA_ROOT/betfair-live/captured`) and in `raw`.

**The values are invented; the shape is not.** Every test that reads this
sample compares two readings of the same bytes, so ids, prices, sizes and times
only need to be coherent. What must never be invented is the shape, which is
how PRD #95 shipped three broken mappers. `SyntheticCaptureShapeTest` fails the
build if any key path, JSON type, co-occurring key set or enumerated value here
is missing from `../capture-shape.json`. `CaptureShapeManifestIT` reads that
manifest off the real corpus (`./mvnw -pl acquisition -Preplay verify`).

Two long captures and two nearly-empty ones, deliberately, mirroring the real
sample they replaced: the short pair are markets the recorder attached to and
got almost nothing from, which is the shape that makes an off-by-one in framing
visible. The first file sorts first and has to carry a suspension and a
settlement, because the projection tests read those from it. The first two
receive before 15:00Z on 2026-08-29 and the last two after, because the capture
load assigns messages to sessions by that window. The generator's docstring
lists what each file exercises.

Line counts include each file's leading `_meta` header, which is **not** a
message. Every count assertion in the tests derives its expectation by reading
these files directly, never from the framer under test.

The generator is deterministic (fixed seed, zero gzip mtime), so regenerating
reproduces these bytes. A different sha256 means the generator changed.
